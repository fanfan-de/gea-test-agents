# Computer E2B 测试提示词

每项测试以实际 Tool 返回值验收，逐条发送，不并发启动场景。开始前确认目标 Agent 版本和所选 provider；构建成功不等于运行通过。

1. 基础对话：“基础检查。”预期 `COMPUTER_E2B_AGENT_OK`；这里只验证对话。
2. 初始化：“实际调用 computer_info，展示 provider、目录、capabilities、Python 版本和 filesystemProbe 的每一项。不要读取任何密钥。”预期 provider 为 e2b，六个文件检查都 true。
3. 文件和参数：“调用 files_probe，mode 为 write，text 为 `provider-e2b-note-中文-001`。展示真实读回文本和二进制 hex、argv/env/stdin 检查结果。”预期 matches、binaryMatches 为 true，resultHex 为 `00ff8000ff`。
4. 普通运行文件复读：“只调用 files_probe，mode 为 read，不能先写 note。”下一次普通 Run 预期 found: false；如果这是显式 retained idle Session，则单独注明运行模式。
5. 成功命令：“只调用 command_probe 的 success 场景。”预期 exitCode 0，stdout 包含 COMMAND_OK 和真实工作目录。
6. 非零命令：“只调用 command_probe 的 nonzero 场景。”预期 exitCode 7，stderr 包含 EXPECTED_NONZERO；不能把正常非零退出描述为协议故障。
7. 超时：“只调用 command_probe 的 timeout 场景，如实展示实际错误、耗时和 expectedTimeout，不编造 exitCode。”
8. 后台 kill：“只调用 command_probe 的 terminate 场景，展示 processId、readinessOutput、killRequested 和实际退出结果或 error。”应先观察 READY_TO_KILL，再确认 kill 请求完成；不承诺具体退出码或信号。
9. 交互输入：“只调用 command_probe 的 interactive 场景。”预期 stdout 为 `interactive $HOME\n中文`，stderr 为 EOF_RECEIVED，exitCode 0。
10. Tool 权限：“调用 permissions_probe，检查两个操作都 allowed: false、denied: true，并展示真实拒绝消息。”
11. Skills：“调用 readonly_skill_probe，确认 readable、unchanged、writeDenied 均为 true，展示实际探测文件路径。”
12. 应用协议：“调用 application_probe，展示 supported/status。若 unsupported，明确当前 E2B Native 未实现 v1，不能假造 ID/events。”

验收报告逐项列工具、实际观测和通过/失败/不支持。不要把普通对话、file smoke 或构建校验冒充其他项目已通过。保留 note/seed/info；不清空 workspace，不输出 secret，不通过飞书 Connector 执行 Computer 测试。
