# 飞书测试提示词

先配置 Preview 的测试飞书应用与允许的发送人，确认 `feishu-bot` receiver 为 `ready`，然后私聊机器人逐条发送。Studio Playground 先发送「实际调用 `feishu__api__connect`，只返回真实授权链接，不执行业务操作」，本人打开链接完成独立 Feishu Connection，再继续。

## 机器人与官方 CLI

1. 「这是飞书机器人收发测试。请回复 `飞书 Channel 已收到`，不要调用业务工具。」确认在当前私聊内回复。
2. 「读取 `feishu__lark-cli` Skill，通过实际飞书 Connector 调用 `argv=["skills","list"]`。展示真实退出码、输出与错误；不要在 Computer 中安装或执行 CLI。」
3. 「通过同一 Connector 读取 `lark-doc` 官方 Skill，再查询文档读取的 help/schema。暂时不要读取或修改我的文档。」
4. 「以 `--as bot` 读取这个已授权测试文档：〈替换为你的测试文档链接〉。按官方 Skill 构造命令，只读，不修改。报告真实结果与错误。」
5. 「以 `--as user` 读取同一测试文档。缺少授权时展示个人授权链接，不切换身份，不伪造内容。」发送人本人授权后重新发送本条。
6. 「以同一身份读取这个未授权文档：〈替换为未授权文档链接〉。拒绝时如实报告，不改身份，不返回空成功。」

## 会话隔离

第一位测试发送人：「记住我的测试词 `飞书用户甲-20261010`，稍后我会询问。」

另一位允许的发送人私聊：「此前我告诉你的测试词是什么？」第二位不能读取第一位的测试词。

第一位继续私聊：「刚才我的测试词是什么？」检查同会话记忆与正确回复目标。

## 写入或独立消息

准备好可修改资源后明确指定目标与操作，例如：「在〈测试文档链接〉末尾添加一行 `飞书写入验收-20261010`。」超时或取消后先核对目标，避免重复写入。

独立发消息也需要明确提供测试收件目标和正文。普通回答由 Channel 投递，不需要额外调用发消息工具。

## 可选 Computer 辅助测试

1. 调用 `computer_info`，报告真实 chatId、scope、目录与能力。
2. 调用 `files_demo` 写入「飞书 Agent 的辅助文件测试」，读回结果；后续 `command_demo` 的 success 场景可验证持久性。
3. 调用 `binary_program`，label 为字面值 `hello $HOME`，检查真实 `resultHex=00ff8000ff`。
4. 逐条调用 `command_demo` 的 nonzero、timeout、terminate，引用实际退出码或错误，不并发。
5. 调用 `permissions_probe`，确认写文件和命令 allowed 均为 false。

Computer 工具不用于执行飞书 CLI，不应出现应用 Secret 或个人凭据。
