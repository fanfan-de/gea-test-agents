# 手动体验提示词

在 Builder 选择 Preview 和操作环境后，新建会话逐条发送。为区别环境，每轮使用新的唯一标记，如 `体验-20261021-001`；已有同名文件时改用新文件名。

1. “调用 computer_targets，展示挂载列表和 primary。只告诉我后续默认操作的 targetMountId，先不执行命令或读取文件。”
2. “在上一步 primary 上，只用 bash 检查 pwd、uname -s、id 和 command -v node；若 Node 可见，再查询 node --version。不读取环境变量，不扫描目录。展示 targetMountId 和实际输出。”
3. “在相同目标创建 computer-experience 目录，用 writeFile 新建 computer-experience/note-001.txt，内容为两行：标记=体验-20261021-001、阶段=已创建。若已有此文件则停下，不覆盖。”
4. “在相同目标用 readFile 读出这个文件，再用 editFile 仅将阶段=已创建改为阶段=已编辑，最后读取确认。”
5. “在相同目标用 applyPatch 新建 computer-experience/extra-001.txt，内容是 patch-ok-体验-20261021-001。不要改其他文件。”
6. “在相同目标，依次用 listDirectory 列 computer-experience，用 findFiles 在此子目录查找本轮 txt 文件，用 searchText 在此子目录搜索体验-20261021-001。不要扩大搜索范围。”
7. “在相同目标用 bash 只读取本轮 note-001.txt 和 extra-001.txt，并计算 sha256sum，和之前工具读到的内容核对。不要修改文件。”
8. 同一会话再发：“在相同目标只用 readFile 读取本轮 note-001.txt，验证标记和已编辑阶段仍保留，不补写。”
9. 新建默认环境会话：“先列 computer_targets，再在 primary 上只读取 computer-experience/note-001.txt；不存在就如实报告，不创建或补写。” 默认环境新会话应隔离；用户目录可能共享，按真实结果判断。

多环境体验：新建会话，勾选两个已经授权的环境。先列 computer_targets，记下两个 ID，再发送：“仅在 targetMountId 为 `<第一个ID>` 的 computer-experience/env-001.txt 写入 first-体验-20261021-001；确认不存在再写。然后在 `<第二个ID>` 只读取同一路径，不补写，报告每个结果的 mountId。” 文件不存在能帮助观察两个目标的独立性；如果原本共享实际目录，按读到的结果报告，不声称隔离。两个 Computer 之间不会自动同步。

清理可选：“只删除本轮明确创建的 note-001.txt、extra-001.txt 和 env-001.txt，不清空目录，不动其他体验记录。” 清理时仍指定原 targetMountId；未知是否存在的文件先检查。
