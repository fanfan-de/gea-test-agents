# Computer Device 测试提示词

以下消息逐条发送，等待上一条完成。使用新建测试 Chat；不得操作用户其他文件。工具结果为真实数据时才判定通过。

1. 实际调用 computer_info，报告真实 chatId、scope、roots、capabilities 和 onSession 的 files；核对 streamedBytes=1048576、streamMatches=true、binaryHex=00ff8000ff、textMatches=true、renameObserved=true、removeObserved=true。不调用其他工具。
2. 实际调用 files_probe，mode=write，text=LOCAL_PROVIDER_唯一测试词。只报告写入后的真实文本和路径。
3. 在同一 Chat 后续消息实际调用 files_probe，mode=read；不重写，验证此前测试词仍存在。
4. 新建另一个 Chat，实际调用 files_probe，mode=read；不写入。按 found/text 报告该 provider 的实际共享行为；本机 project/device 根可能共享，不要求为空。
5. 实际调用 command_probe，scenario=success，label 为字面 hello $HOME。核对真实 stdout JSON 的 label=hello $HOME、stdin=你好 stdin 加换行；不把变量展开后的内容写作成功。
6. 实际调用 command_probe，scenario=nonzero。核对真实 exitCode=7 和 stderr，不调用其他工具。
7. 实际调用 command_probe，scenario=timeout。报告真实 timeout/abort/interrupted 错误，不补跑。
8. 实际调用 command_probe，scenario=terminate。报告真实 processId、killRequested=true 和返回的退出状态或 process terminated 错误；不编造退出码。
9. 实际调用 permissions_probe，核对 fileWrite.allowed=false、commandRun.allowed=false，引用真实错误。
10. 实际调用 readonly_skill_probe，核对 matchesBundle=true、unchanged=true、apiWrite.allowed=false。仅说明文件 API 保护，不说明 trusted shell 隔离。
11. 实际调用 application_probe，label 为字面 hello $HOME。如果 unsupported 就明确能力未宣告；有协议时报告真实 command state、stdout/stderr 事件、result.bin 的 dataBase64=AP+AAP8=，不伪造事件。

当前 device 预期 application v1 为 unsupported；这项输出不能作为 v1 验收通过。
