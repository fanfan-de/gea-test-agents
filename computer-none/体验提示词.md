# 不配置 Computer：手动体验提示词

在 Builder 选择 `Computer-None-Test` 的 Preview，新建会话，不选择任何 Computer。逐条发送，展开工具调用核对真实输入和输出。每轮使用新的文件标记；以下标记 `20261021-001` 只是示例。

1. “请用一句中文介绍自己，不调用任何工具。”
2. “实际调用 computer_targets，展示原始挂载列表和 primaryMountId。先不执行命令或读取文件。”
3. “实际调用 calculate_sum 计算 [37, 58, -12]，展示工具返回的 count 和 sum，不要只用心算回答。”预期数值是 count=3、sum=83。
4. “即使挂载列表为空，也请实际调用一次 bash，命令为 printf 'computer-none-shell-probe\n'，不填 targetMountId。展示真实结果或错误；如果模型根本没有 bash 工具，直接说明不可调用。不要重试、补配置或切换后端。”
5. “先确认挂载列表仍为空，再实际调用一次 readFile 读取 /workspace/computer-none-probe-20261021-001.txt，不填 targetMountId。没有工具或调用失败就如实说明，不创建文件，不把错误改写成文件不存在。”
6. “先确认挂载列表仍为空，再实际调用一次 writeFile 写入 /workspace/computer-none-probe-20261021-001.txt，内容是 computer-none-file-probe-20261021-001，不填 targetMountId。展示真实结果或错误，不重试、不补配置；如果意外发现任何挂载，停止写入并报告。”
7. “再实际调用 calculate_sum 计算 [4, 9]，验证 shell/文件探针之后普通自定义工具仍可工作。最后按真实工具记录列出本轮结果，未运行的项目标记未运行。”

如果 UI 不提供 Computer 选择器，也记录这个现象。若挂载列表不为空，此会话不满足“无挂载”条件，先停止 shell/文件探针并新建会话。内置工具可能在运行时筛选后不提供给模型；“不可调用”和“实际调用后的失败”应分别记录，不要让 Agent 猜测不存在的工具输出。
