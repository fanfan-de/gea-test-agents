# Computer Default 测试提示词

先确认当前 Preview Agent 来源，再逐条发送。工具串行执行，保留实际返回值；不要要求模型根据前一次回答代替调用。

1. 基础对话：“基础检查。”预期 `COMPUTER_DEFAULT_AGENT_OK`，只证明对话可用。
2. 环境：“只调用一次 computer_info，展示 provider、chatId、scope、roots 和 capabilities，不读取密钥。”预期 provider 为 default；后续两个后台用例是否可用取决于 processes。
3. 运行时：“只调用一次 runtime_probe，展示实际 Node 版本、系统、cwd 和 argvMatches/environmentMatches/stdinMatches。”三项都应为 true。
4. 文件：“只调用一次 files_probe，mode 为 write，text 为 `本轮唯一-token-中文-001`，展示四项匹配和二进制 hex。”预期 matches、binaryMatches、unicodeMatches、commandFileMatches 都为 true，resultHex 为 `00ff8000ff`。每轮替换唯一 token。
5. 持久化：“只调用一次 files_probe，mode 为 read，不能先写 note。”同一 Chat 的后续 Run 应 found 为 true，text 与上一步完全一致。
6. 隔离：新建 Chat 后发送上一步提示，预期 found 为 false。read 的 passed 只代表观察成功，不代表 note 存在。
7. 成功：“只调用一次 command_probe，scenario 为 success。”预期 exitCode 0，stdout 包含 COMMAND_OK 与实际目录。
8. 非零：“只调用一次 command_probe，scenario 为 nonzero。”预期 exitCode 7、stderr 包含 EXPECTED_NONZERO；正常非零退出不等于协议故障。
9. 超时：“只调用一次 command_probe，scenario 为 timeout，展示实际错误、elapsedMs 和 expectedTimeout，不补造 exitCode。”真实超时可通过，普通故障、未知结果和清理失败应 error。
10. 终止：“只调用一次 command_probe，scenario 为 terminate，展示 processId、readinessOutput、killRequested 和实际终态。”先观察 READY_TO_KILL，再确认 kill；无 processes 应 unsupported。
11. 输入：“只调用一次 command_probe，scenario 为 interactive。”预期 stdout 为 `interactive $HOME\n中文`、stderr 为 EOF_RECEIVED、exitCode 0；无 processes 应 unsupported。
12. 权限：“只调用一次 permissions_probe，展示两项拒绝的实际消息。”两项 allowed 为 false、denied 为 true。
13. Skills：“只调用一次 readonly_skill_probe，展示路径及 readable、unchanged、writeDenied。”三项都应为 true。

报告逐项列通过/失败/不支持及实际证据。不要调用已移除的 application_probe，不声称测试了底层 v1 协议或图形桌面。实际 Studio 验收与本地 Node 行为测试分别记录；构建、打包成功不能代替真实 Run。
